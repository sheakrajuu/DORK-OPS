Terminal basics: how to read a command

A terminal command is text entered into a shell such as Bash. This reference formats examples for you to inspect or copy; it does not run them.

printf 'alpha\nbeta\n' | grep 'beta'
  1. printf is the first program; the quoted text is its argument.
  2. | is a shell operator. It sends the first program’s output into the next program.
  3. grep 'beta' is the second program and argument; it prints matching lines.
  4. The expected output is beta. Each program only sees the arguments passed to it; the shell handles the pipe.

Command, options, and arguments

For nmap -p 80 127.0.0.1, nmap is the program, -p is an option, 80 is that option’s value, and 127.0.0.1 is the target argument. A word in angle brackets, such as <input-file>, is an instruction to substitute your own value—not text to type literally.

Three common ways commands connect

  • first && second: run second only when first succeeds.
  • first || second: run second only when first fails.
  • first ; second: run both in order, regardless of the first result. A pipe (|) is different: it passes output from one program into another.

Use quotes around one argument that contains spaces, for example --output 'lab results.txt'. Quotes group text for the shell; they do not make an unsafe command safe.

Pause before redirecting output: > file replaces an existing file, while >> file appends to it. Check the destination path before running either form. Use --help or man toolname to check options for the installed version.
